## 摘要
将大型语言模型（LLM）个性化已成为一个核心挑战，因为LLM被部署在推荐、搜索、对话和内容生成等场景中——在这些场景下，相同的查询应根据不同用户给出不同的答案。一个有前景的方法是总结每个用户的交互历史为自然语言记忆或画像，并将其添加到提示词前以促进个性化。现有方法通过从标记的下游任务中获得的显式奖励来学习此类画像生成器，但这些方法代价高昂且稀疏，因为它们需要为每个目标任务提供带注释的监督。针对这一挑战，我们提出了通过画像进行双向用户建模（BUMP），这是一个自监督框架，无需任何下游标签即可训练画像生成器。具体来说，给定用户的交互历史，我们使用GRPO训练LLM在双向批内排序目标下生成自由形式的文本画像：一个小型LLM判断器衡量（i）生成的画像作为查询时，将用户自己的保留交互排在批内其他用户的交互之上的效果，以及（ii）一个保留交互作为查询时，将用户自己的画像排在批内其他用户画像之上的效果。两个方向都使用多正例NDCG进行评分，并合并为每次rollout的密集奖励；批内的其他用户提供免费的负例，因此每个训练样本仅从原始交互日志中获得监督。在LaMP基准上的评估显示，BUMP在匹配或超越依赖标记奖励的闭源API和先前方法的同时，训练时无需任何任务标签。

## Abstract
Personalizing large language models (LLMs) has become a central challenge as LLMs are deployed across recommendation, search, dialogue, and content generation -- settings where the same query should yield different answers given different users. A promising route is to summarize each user's interaction history into a natural-language memory or profile and prepend it to the prompt to facilitate personalization. Existing methods learn such profile generators with explicit rewards derived from labeled downstream tasks, which are expensive and sparse as they require annotated supervision for every target task. In light of this challenge, we introduce Bidirectional User Modeling via Profiles (BUMP), a self-supervised framework that trains a profile generator without any downstream labels. Specifically, given a user's interaction history, we use GRPO to train an LLM to emit a free-form textual profile under a bidirectional in-batch ranking objective: a small LLM judge measures (i) how well the generated profile, used as a query, ranks the user's own held-out interactions above interactions from other users in the batch, and (ii) how well a held-out interaction, used as a query, ranks the user's own profile above profiles of other users. Both directions are scored with multi-positive NDCG and combined into a dense reward per rollout; other users in the batch supply free negatives, so every training example yields supervision from raw interaction logs alone. Evaluated on the LaMP benchmark, BUMP matches or outperforms closed-source APIs and prior methods relying on labeled rewards, while requiring no task label at training.

## 1. 核心问题与整体含义（研究动机和背景）

**问题**：大型语言模型（LLM）在推荐、搜索、对话、内容生成等场景需要个性化，即相同查询对不同用户应输出不同答案。一个有效方法是将用户交互历史总结为自然语言画像（profile），并拼接到提示词前。然而，现有画像生成器通常**依赖下游任务标签**（如分类、点击预测）来定义奖励信号，训练成本高、标签稀疏，且每个新任务都需要重新收集标注数据，限制了泛化性。

**动机**：希望仅从用户的**原始交互日志**中学习生成高质量画像，无需任何任务标注，从而降低成本、提高跨任务迁移能力。

## 2. 提出的方法论

### 核心思想
- **自监督双向排序**：将画像生成转化为两个互补的排序任务：
  - **前向（profile→history）**：用生成的画像作为查询，将用户自己的保留交互排在批次内其他用户的交互之前。
  - **后向（history→profile）**：用一个保留交互作为查询，将用户自己的画像排在批次内其他用户的画像之前。
- 两个方向都使用**多正例NDCG**（Multi-positive NDCG）作为评分，并合并为密集奖励信号，通过**GRPO**（Group Relative Policy Optimization）优化策略网络πθ。

### 关键技术细节
- **历史划分**：每个用户的历史分为可见前缀（Hvis，前15项）和保留部分（Hho，后1项）。生成器基于Hvis输出文本画像su。
- **奖励设计**：
  - 前向奖励 \(R_u^{fwd}\)：用su查询，对P+2个候选项（P个正例+2个批内负例）排序，计算多正例NDCG。
  - 后向奖励 \(R_u^{bwd}\)：用每个保留交互查询，对1+K个画像（1个正例+K个负例）排序，取平均单正例NDCG。
  - **位置去偏**：对每个排序任务采样M个随机展示顺序（M=2），平均NDCG以消除LLM排序的位置偏差。
  - **长度惩罚**：对超过长度阈值T的奖励进行指数惩罚，防止产生通用的冗长画像。
  - 总奖励：\(R(s_u) = \bar{R}_u^{fwd} + \bar{R}_u^{bwd} - R_{len}(s_u)\)。
- **BUMP+（增强版）**：在批内负例中引入**硬负例挖掘**：前向用BGE嵌入选择与用户可见历史中心不相似的自身保留项；后向选择与用户历史中心最相似的批内用户画像作为负例，增加区分难度。
- **优化与使用**：GRPO训练策略，每组8个rollout；训练后冻结生成器，离线为每个用户生成一次画像并缓存；下游任务（分类/回归/生成）时，将画像拼接到输入前，用LoRA微调一个新骨干网络。

### 算法流程（文字描述）
1. 批量采样B个用户，每个用户取15个可见历史项，1个保留项。
2. 策略πθ为每个用户生成8个候选画像（group size=8，GRPO）。
3. 冻结的小型LLM判断器J分别计算前向和后向NDCG，并合并为总奖励。
4. 用GRPO算法更新πθ，最大化期望奖励。
5. 训练完成后，用贪心解码为每个用户生成一个画像，缓存供下游使用。

## 3. 实验设计

### 数据集与基准
- **LaMP基准**（Salemi et al., 2024b）：标准LLM个性化测试集，涵盖6个公开任务（LaMP-1至5、7，LaMP-6未公开），包括：
  - 分类：LaMP-1（引用识别）、LaMP-2（电影标签15分类）
  - 回归：LaMP-3（产品评分1-5）
  - 生成：LaMP-4（新闻标题）、LaMP-5（论文标题）、LaMP-7（推文改写）
  - 采用时间划分（time-based split），每个用户最后一项作为测试。

### 对比基线
- **无个性化**：不添加任何用户信息。
- **原始历史**：拼接最近15个历史项。
- **零样本画像**：用不同LLM直接生成画像：Qwen3-4B-Instruct、Gemini-3-Flash、Gemini-3-Pro。
- **直接奖励（Direct Reward）**：使用下游任务标签做奖励训练相同策略（GRPO），与BUMP仅奖励信号不同。
- 所有方法共享同一**LoRA-SFT**下游微调流程，唯一区别是用户前缀。骨干网络固定为Qwen3-4B-Instruct。

### 评估指标
- 分类：准确率、F1
- 回归：MAE、RMSE
- 生成：ROUGE-1、ROUGE-L

## 6. 主要结论与发现

1. **自监督可以代替任务监督**：BUMP+在9/11指标上匹配或超过依赖下游标签的Direct Reward（直接奖励），证明精心设计的自监督奖励足以替代昂贵标注。
2. **4B开源模型击败最强闭源**：BUMP+在所有11个指标上超过Gemini-3-Pro，BUMP在9/11上胜出，说明小模型经自监督RL可媲美大模型零样本。
3. **双向设计不可或缺**：仅前向或仅后向均导致性能下降，双向同时保证描述充分性和辨识性。
4. **生成任务原始历史更强**：在ROUGE评分任务（LaMP-4/5/7）中，原始历史优于所有画像方法，因为ROUGE奖励字面重叠，而画像牺牲了微观风格。
5. **硬负例挖掘有效**：BUMP+通过BGE选取更难的负例，显著提升分类和回归任务。
6. **策略规模仍有提升空间**：8B策略优于4B，而判断器4B已饱和。

## 7. 优点

- **完全自监督**：无需任何下游标签，从原始交互日志中提取监督，成本低、可扩展。
- **框架通用**：输出为自由文本画像，可缓存复用，兼容任意下游LLM（冻结或微调）。
- **设计精巧**：双向排序模拟对比学习中的对称性，避免了单边目标导致的信息坍塌。
- **实用性强**：位置去偏、长度惩罚、硬负例挖掘等细节增强了训练稳定性。
- **开源复现友好**：基于Qwen3-4B，训练在单台8×H100即可完成，无需超大集群。
- **强竞争力**：在LaMP上超越大参数闭源API和多种有监督基线。

## 8. 不足与局限

1. **LLM作为判断器的固有偏差**：存在位置偏好、风格偏好、自我偏好等（论文已做位置去偏，但未完全消除）。
2. **判断器容量瓶颈**：候选池扩大时（K=16）判断器排序能力下降，出现幻觉噪声（表4）。
3. **硬负例挖掘依赖近似相似性**：BGE嵌入的“困难”并不总是真实混淆，过度挖掘可能引入噪声（表5中Jhard=6有退化）。
4. **生成任务上不如原始历史**：画像抽象掉用户写作风格，导致ROUGE分数下降，可能需要保留部分原始文本。
5. **未验证跨域/零样本迁移**：论文仅在LaMP同一基准的不同任务间间接测试泛化，但未在完全不同领域（如从电影推荐迁移到学术搜索）进行实验。
6. **可解释性**：文本画像虽比embedding更可读，但RL优化可能产生不可控的表达，用户画像的安全性与隐私需进一步研究。
7. **计算资源**：虽然单节点可运行，但GRPO需要同时运行策略、rollout和判断器，实际部署时仍需一定算力。
