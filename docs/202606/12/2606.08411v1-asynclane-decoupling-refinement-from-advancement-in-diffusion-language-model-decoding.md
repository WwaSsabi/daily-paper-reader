## 摘要
块状半自回归解码是扩散大语言模型（DLM）的标准推理范式，但它对块之间施加了严格的依赖关系：当前块必须完全解码或其去噪预算耗尽后，下一个块才能开始。我们观察到，一旦某个块暴露出可靠的分隔符边界或稳定的语义前缀，续写生成无需等待每个残余token被解决。我们提出AsyncLane，一种无需训练的解码调度器，它将精炼与推进解耦。AsyncLane在观察到的分隔符边界处将生成通道分叉为精炼通道和续写生成通道：前缀保持可编辑，而续写在前缀精炼完成之前推进。生成的通道树记录解码依赖关系和输出顺序，同时执行在活跃通道集上进行。为了使这种异步调度在双向注意力下高效，AsyncLane结合了共享前缀通道批处理、前瞻草稿重用、级联终止以及紧凑缓存刷新与刷新logit重用，防止模型调用成本随通道数量直接扩展。AsyncLane是块状DLM采样器的即插即用替代方案，无需重新训练。在数学推理和代码生成实验表明，AsyncLane持续提高吞吐量，同时保持有竞争力的质量。在LLaDA和Dream骨干上，所有评估的基准长度设置中AsyncLane实现了最高的TPS；相对于最快的竞争基线，它在LLaDA上达到2.95倍的峰值加速，在Dream上达到3.04倍，在更长的生成预算下增益尤其显著。

## Abstract
Block-wise semi-autoregressive decoding is the standard inference paradigm for diffusion large language models (DLMs), but it imposes a strict dependency between blocks: the next block cannot begin until the current block is fully decoded or its denoising budget is exhausted. We observe that once a block exposes a reliable delimiter boundary or stable semantic prefix, continuation generation need not wait for every residual token to be resolved. We propose AsyncLane, a training-free decoding scheduler that decouples refinement from advancement. AsyncLane forks a generate lane at observed delimiter boundaries into a refine lane and a continuation generate lane: the prefix remains editable, while the continuation advances before prefix refinement finishes. The resulting lane tree records decoding dependencies and output order, while execution proceeds over the active lane set. To make this asynchronous schedule efficient under bidirectional attention, AsyncLane combines shared-prefix lane batching, lookahead draft reuse, cascading termination, and compact cache refresh with refresh-logit reuse, preventing model-call cost from scaling directly with the number of lanes. AsyncLane is a drop-in replacement for block-wise DLM samplers and requires no retraining. Experiments on mathematical reasoning and code generation show that AsyncLane consistently improves throughput while maintaining competitive quality. Across LLaDA and Dream backbones, AsyncLane achieves the highest TPS in all evaluated benchmark-length settings; relative to the fastest competing baseline, it reaches peak speedups of 2.95x on LLaDA and 3.04x on Dream, with especially large gains under longer generation budgets.

# 中文总结：AsyncLane

## 1. 核心问题与整体含义（研究动机与背景）

扩散语言模型（DLM）采用**块状半自回归解码**：生成区域被划分为多个块，按顺序逐一解码。每个块必须完成其所有去噪步骤（或耗尽去噪预算）后，下一个块才能开始。这种**块完成屏障**（block completion barrier）将**当前块内低置信度位置的精炼**与**向前一区域的推进**这两个本质不同的操作强制串联在一条关键路径上。作者观察到，一旦当前块暴露出可靠的分隔符边界（如句号、换行符）或稳定的语义前缀，后续的生成不必等待每个剩余 token 被完全解决。因此，核心问题是：**能否在不重新训练模型的前提下，将精炼与推进解耦，实现异步解码？**

## 2. 方法论：核心思想与关键技术细节

### 2.1 核心思想
AsyncLane 提出**基于活跃车道的异步调度**，用一组活跃车道（lane）取代单个全局块指针。每个车道有角色（生成/精炼）、起始位置、当前 token 状态和局部去噪步数。

### 2.2 关键技术细节

- **边界触发的分支与精炼（Branch-and-Refine）**  
  当一个生成车道检测到任务相关的可靠分隔符边界（数学推理：句号；代码生成：换行符），且填充率≥ρ_min、步数≥t_min，则执行分支：将分隔符前的部分分配给**精炼车道**（继续抛光），分隔符后的部分分配给**新的生成车道**（立即开始推进）。精炼车道与生成车道同时活跃，实现“前缀可编辑，续写提前启动”。

- **活跃车道调度与输出收集**  
  用车道树记录父子关系；每次迭代更新活跃车道，执行分支，然后根据有效前缀长度决定是否生成后继生成车道（级联终止）。输出树时，精炼孩子先于生成孩子，叶子截断在第一个 mask 或 EOS 处。

- **高效异步执行机制**  
  - **共享前缀车道批处理**：分叉出的兄弟车道共享分支前缀状态，可分组进行批处理前向，使模型调用次数 NFE 与组数（≤活跃车道数）相关，而非与车道数直接线性增长。  
  - **前瞻草稿重用**：生成车道前向时对高置信度非 EOS 的未来窗口写回草稿，后续生成车道继承这些草稿，减少掩码位置。  
  - **级联终止**：若生成车道完成后的有效前缀长度为零（遇到 EOS 或无法解析的掩码），则不再生成后继车道，剪除下游计算。  
  - **紧凑缓存刷新与刷新 logit 重用**：只刷新有意义前缀加一小段额外区域，且刷新 logit 在下一次前向中被重用，摊还刷新成本。

### 2.3 形式化表示（文字说明）
车道定义为 ℓ = (role, start, state, denoising_step)。分支操作 F(ℓ, p) 在有效分隔符位置 p 处分裂成 ℓ_refine 和 ℓ_generate。整体 NFE 公式为：NFE = 1 + ∑|G_t| + N_refresh - N_reuse，成本与共享前缀组数和有效前沿长度相关，而非车道节点数。

## 6. 主要结论与发现

1. AsyncLane 在所有基准设置下实现最高 TPS：相比最快竞争基线，LLaDA 和 Dream 骨干峰值加速分别达 **2.95×** 和 **3.04×**，且长生成预算下优势更显著。  
2. 质量保持竞争：在 MATH 上甚至略优于部分基线，在代码生成任务上与加速基线持平或略高。  
3. 解耦的两个要素（精炼+早期推进）缺一不可：仅早期推进无精炼导致准确率大幅下降；仅精炼无早期推进则吞吐量提升有限。  
4. 高效机制显著降低 NFE/token：前瞻草稿重用和刷新 logit 重用对保持质量和提升吞吐量均关键。

## 7. 优点

- **无需训练**：即插即用，可直接替换现有块状采样器，兼容任意预训练 DLM。  
- **创新性**：首次系统性地将 DLM 解码中的精炼与推进解耦，通过车道分叉实现异步执行，而非简单调整块大小或批处理。  
- **高效性设计**：共享前缀批处理、草稿重用、级联终止、紧凑缓存刷新等机制有效控制模型调用次数，避免活跃车道数增加带来的计算成本线性增长。  
- **可推广性**：在 LLaDA 和 Dream 两种不同结构的 DLM 中均取得一致改进，验证了方法的骨干无关性。  
- **实验全面**：覆盖数学推理与代码生成，多种长度设定，多组消融实验系统分析各组件贡献。
