## 摘要
长篇输入序列是大型语言模型中文档理解和多步推理的核心，但注意力的二次方成本使得推理既内存密集又缓慢。上下文蒸馏通过将上下文信息压缩到模型参数中来缓解这一问题，最近的工作如Doc-to-LoRA将上下文蒸馏摊销为单个前向传递，每个文档生成一个LoRA适配器。然而，为所有查询生成单个整体适配器会导致无关查询干扰、组合回忆能力有限以及长文档推理的可扩展性差。为了解决这些挑战，我们提出了Doc-to-Atom（Doc2Atom），一种组合式参数化记忆框架，将每个文档分解为语义类型化的知识原子。每个原子被编译成一个独立的微型LoRA适配器和一个来源检索键。在推理时，轻量级查询路由器选择并仅将相关原子组装成查询特定的适配器，然后注入冻结的基础模型。整个系统通过多目标蒸馏框架进行端到端训练。在六个不同的问答基准上的实验表明，Doc2Atom在降低文档内部化内存成本的同时，优于Doc-to-LoRA基线。

## Abstract
Long input sequences are central to document understanding and multi-step reasoning in Large Language Models, yet the quadratic cost of attention makes inference both memory-intensive and slow. Context distillation mitigates this by compressing contextual information into model parameters, and recent work such as Doc-to-LoRA amortizes context distillation into a single forward pass that generates one LoRA adapter per document. However, producing a single monolithic adapter for all queries leads to irrelevant-query interference, limited compositional recall, and poor scalability to long-document reasoning. To address these challenges, we propose Doc-to-Atom (Doc2Atom), a compositional parametric memory framework that decomposes each document into semantically typed knowledge atoms. Each atom is compiled into an independent micro-LoRA adapter and a provenance retrieval key. At inference time, a lightweight query router selects and assembles only the relevant atoms into a query-specific adapter, which is then injected into a frozen base model. The entire system is trained end-to-end through a multi-objective distillation framework. Experiments on six diverse QA benchmarks demonstrate that Doc2Atom outperforms Doc-to-LoRA baselines while reducing the memory cost of document internalization.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **问题**：大型语言模型（LLM）在处理长序列输入时，由于注意力的二次复杂度（quadratic cost），推理变得内存密集且速度慢。上下文蒸馏（Context Distillation）通过将上下文信息压缩到模型参数中来解决此问题。近期工作 Doc-to-LoRA 将上下文蒸馏摊销为单个前向传递，为每个文档生成一个 LoRA 适配器。
- **现有局限**：Doc-to-LoRA 为所有查询生成一个**单一的、整体的适配器**，导致三个关键问题：
  - **无关查询干扰**：当查询与文档内容无关时，适配器仍会修改模型隐藏状态，造成干扰。
  - **有限的组合式召回**：对于包含多种异构事实的文档，扁平的低秩适配器无法为每个查询有选择地提供证据，因此组合式召回能力差。
  - **长文档可扩展性差**：随着文档长度增加，固定秩的适配器必须将越来越多的内容压缩到同一参数预算中，限制了长文档推理的性能。
- **研究动机**：提出一种**组合式的参数化记忆框架**，将文档分解为更细粒度的“知识原子”，以便按查询选择性地组合，从而克服整体适配器的弊端。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将文档分解为**语义类型化的知识原子**，每个原子是一个最小的、自包含的信息单元。每个原子被独立编译为：
  - 一个微型 LoRA 适配器（micro-LoRA）；
  - 一个溯源检索键（provenance retrieval key）；
  - 可选的紧凑 KV 原型（micro-KV）。
  
  在推理时，一个**两阶段查询路由器**识别与当前问题最相关的一小组原子，将它们各自的微型 LoRA 适配器组合（通过路由权重求和）成一个查询特定的组合式 LoRA，然后注入到冻结的基础模型中。

- **关键技术细节**：

  1. **数据原子化管道（Data Atomization Pipeline）**：
     - 使用 LLM（MiniMax-M2.5）将每个文档分解为不重叠的、语义自包含的知识原子，带有丰富的元数据（语义类型、源跨度、检索文本、答案承载标志、抽象级别、冲突组、置信度、原子间关系）。
     - 生成无关探测问题（Irrelevant Probes）来训练路由器拒绝与文档无关的查询。
     - 使用问题-原子标注（Question-to-Atom Annotation）为每个问题标注出金原子、支持原子和干扰原子。

  2. **组合式记忆框架（Compositional Memory Framework）**：
     - **共享文本编码器**：复用冻结基础模型的前 `L_enc` 层作为原子和查询的编码器，加入可学习的投影头得到嵌入向量。
     - **原子级记忆编译器**：输入原子嵌入，通过共享主干 MLP 和四个并行头，输出：① 溯源键（用于路由）；② 微型 LoRA 因子（每个目标模块和记忆层）；③ 可选微型 KV 原型；④ 可选稀疏掩码门控。
     - **两阶段查询路由器**：第一阶段通过余弦最大内积搜索从所有溯源键中检索 top-K 候选；第二阶段可选地使用冻结交叉编码器重排序，加上学习到的元数据偏差，最终选择 top-K 原子并 softmax 归一化为路由权重。
     - **记忆组合器与注入**：将所选原子的微 LoRA 因子按路由权重加权求和，再乘以聚合的稀疏门控，形成查询特定的组合式 LoRA。可选地，将微 KV token 按路由权重缩放后作为紧凑前缀。所有写入限制在最后 `n_L` 个解码器层。

  3. **训练目标（多目标蒸馏框架）**：
     - 教师-学生范式：教师模型使用完整文档+查询推理，学生模型仅用查询+组合式 LoRA，蒸馏学生输出以匹配教师。
     - 损失函数包括：
       - 语言建模损失 `L_LM`（交叉熵）
       - 蒸馏损失 `L_distill`（温度缩放 KL 散度）
       - 路由监督损失 `L_route`（加权二元交叉熵，对干扰原子惩罚更重）
       - 无关查询抑制损失 `L_irrel`（对无关查询的 LoRA 因子施加 L2 范数惩罚）
       - 知识保护损失 `L_protect`（对组合 LoRA 的 ΔW 施加 L2 或零空间投影约束）
       - 稀疏正则化损失 `L_sparse`（推动门控激活率接近目标密度）
       - 组合一致性损失 `L_composition`（与强制使用金掩码的前向传递之间的对称 KL 散度）
       - 其他：冲突组一致性 `L_conflict`、置信度对齐 `L_confidence`。
     - 使用多阶段课程学习：逐步增加检索到的原子数 K，依次激活各损失项，以减少早期耦合冲突。

## 6. 论文的主要结论与发现

- **准确率提升**：Doc2Atom 在两个基础模型上的整体 F1 均优于所有 D2L 基线（Gemma-2：37.99 vs D2L atom 的 29.41；Qwen3-4B：35.72 vs 29.30），提升显著（+8.58 和 +6.42）。零样本 LongBench 子集上，Doc2Atom 有时达到 D2L raw 的 6 倍高。
- **无关查询拒绝能力大幅提升**：在 Gemma-2 上，Doc2Atom 的拒绝 F1 通常在 85% 以上（最高 97.5%），而 D2L 基线大多低于 40%；在 Qwen3 上同样在所有子集上获胜。
- **内存效率**：Doc2Atom 的额外 GPU 内存比 D2L 低 44%（Gemma-2）至 85%（Qwen3），因为激活计算只依赖所选原子数量，与文档长度无关。
- **代价**：更新延迟比 D2L 高（2.10s vs 0.31s 在 Gemma-2 上），但此步骤是离线的，不影响查询推理速度。
- **原子化本身带来增益**：即使使用相同的 D2L 架构，在原子化文档上训练（D2L atom）也比在原始文档上训练（D2L raw）有微弱一致改进（+0.86 / +0.45 F1）。
- **记忆与上下文互补**：将原子记忆与完整上下文同时提供给模型（Doc2Atom + ctx）比单纯使用上下文（Base + ctx）总体 F1 提升 2.26 点，显示原子记忆提供了结构化补充信号。

## 7. 优点：方法或实验设计上的亮点

- **组合原子架构**：首次将文档自我组合的概念引入参数化记忆，每个原子是独立可检索、可写入的知识单元，突破了整体适配器的瓶颈。
- **多目标训练框架**：同时优化语言生成、路由准确性、无关抑制、知识保护、稀疏性和组合一致性，且通过课程学习逐步加入，训练稳定。
- **两阶段路由器**：结合高效检索和精密重排序，加上元数据偏差，实现高召回率高精度的原子选择。
- **知识保护机制**：采用 L2 约束和零空间投影，防止组合适配器覆盖基础模型原有能力，保护了模型在无关查询上的表现。
- **广泛的评估**：涵盖短/长/多跳/零样本，两个不同系列模型，并单独测试拒绝能力，实验设计全面。
- **效率改善**：虽然编译延迟略增，但内存开销大幅下降，有利于部署。

## 8. 不足与局限

- **依赖固定原子分类和分解策略**：当前使用五个预设语义类型和固定分解方案，可能不适用于需要更细或更粗粒度的任务/领域，缺乏自适应性。
- **基础模型规模有限**：实验仅在 2B-4B 大小的冻结模型上进行，未扩展至前沿大模型（如 7B/70B 或更大），这是因为计算资源限制。在更大模型上的表现和扩展性未知。
- **与 ICL 上界仍有差距**：尽管优于参数化基线，但与直接使用完整文档作为上下文的 Base+ctx 相比，仍有约 10 个点的整体 F1 差距。作者承认需要更好的原子内容、路由策略和微 KV 设计来缩小差距。
- **更新延迟较高**：原子编码、记忆编译和两阶段路由增加了编译阶段的延迟（比 D2L 高 3-7 倍），虽然这一步是离线且不对应查询实时推理，但在需要频繁更新记忆的场景中可能成为瓶颈。
- **原子化依赖外部 LLM**：原子分解和问题标注需要额外的 LLM 调用（本文使用 MiniMax-M2.5），增加了预处理成本与可能的标注噪声（尽管有验证步骤）。
- **未与其他参数化记忆方法直接对比**：如 Cartridges、Generative Adapter 等，仅限于与 Doc-to-LoRA 系列比较，可能会遗漏更具竞争力的基线。
